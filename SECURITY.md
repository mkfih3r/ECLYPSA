# Security Policy
At ECLYPSA AI, we take the security of our platform, models, and community seriously. We appreciate the efforts of security researchers and community members who help keep ECLYPSA AI safe for everyone.
---
## Supported Versions
The following table outlines the security update support status for versions of ECLYPSA AI:

| Version | Supported | Security Patches |
| :--- | :--- | :--- |
| `v1.x` | :white_check_mark: | Active support |
| `< 1.0` | :x: | Unsupported — please upgrade |

---
## Reporting a Vulnerability
**Please do not report security vulnerabilities through public GitHub issues, pull requests, or public discussions.**
If you believe you have discovered a security vulnerability in ECLYPSA AI, please report it privately through one of the following methods:
1. **GitHub Private Vulnerability Reporting:** Navigate to the **Security** tab of the repository, select **Report a vulnerability**, and submit your report directly to the maintainers.
2. **Email Disclosure:** Send an email detailing your findings to **security@nexaracademy.com**.
### What to Include in Your Report
To help us evaluate and address the issue efficiently, please include:
- A descriptive title and summary of the vulnerability.
- Proof of Concept (PoC) code or step-by-step instructions to reproduce the issue.
- Impact assessment (e.g., potential unauthorized access, data exposure, remote code execution).
- Affected versions, dependencies, or specific code locations.
- Any potential mitigation or fix if you have one available.
---
## Responsible Disclosure Policy
We ask that all security researchers adhere to the following responsible disclosure guidelines:
- **Maintain Confidentiality:** Keep information regarding the vulnerability private until we have investigated, resolved, and publicly disclosed the issue.
- **Avoid Harm:** Do not access, modify, or delete user data, perform Denial of Service (DoS) attacks, or disrupt operational systems.
- **Act in Good Faith:** Avoid privacy violations, destruction of data, and interruption or degradation of our service during your research.
- **Comply with Laws:** Operate within legal boundaries and avoid unauthorized social engineering, phishing, or physical attacks against our team or infrastructure.
---
## Response Timeline
We are committed to addressing security concerns promptly. You can expect the following timeline upon submitting a report:

| Milestone | Expected Timeframe |
| :--- | :--- |
| **Initial Acknowledgment** | Within **24–48 hours** |
| **Triage & Assessment** | Within **3–5 business days** |
| **Status Updates** | Every **5 business days** until resolution |
| **Patch & Fix Delivery** | Depends on severity (Critical issues prioritized) |

---
## Public Disclosure
Once a fix has been developed, tested, and released across supported versions, we will publish a security advisory detailing the issue and credit the reporter (unless you request to remain anonymous).
Thank you for helping keep ECLYPSA AI and its community secure!
